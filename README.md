# 三院 · 个人工作台

一个无后端、无第三方依赖、无 CDN 的本地个人工作台。除了工作、学习、自媒体、灵感、习惯与情绪记录，还可根据你的「产品全生命周期工作流」导入规划表、自动拆解任务、生成项目甘特图并给出每日提醒。页面使用白底、绿色强调、侧边导航、统一线性图标与模块卡片。

## 运行说明

### 方式一：直接打开

双击 `index.html`，即可在 Edge、Chrome 等现代浏览器中使用。

### 方式二：本地服务

在当前目录执行：

```bash
python -m http.server 8080
```

然后访问 `http://localhost:8080`。

> 如需启用浏览器系统通知，建议使用本地服务方式（`http://localhost`）；直接打开 `file://` 时不同浏览器对通知授权的限制不同。页面内每日提醒在任何方式下都可用。

### 数据保存

- 首次打开自动填入示例数据，之后所有变更自动保存到当前浏览器的 `localStorage`。
- 数据不会上传；更换浏览器、设备或清除网站数据前，请先在左侧点击“导出备份”。
- JSON 备份包含六类记录，以及项目、任务和提醒设置。
- 页面左下角“使用指南”提供运行说明、验收清单和“恢复示例数据”。

## 页面结构

1. **今日总览**：6 张实时统计卡、近 7 日行动图、情绪趋势、接下来要做、今日工作提醒。
2. **AI 拆解**：对话框内输入自然语言或上传任务表，自动拆解成十阶段任务并直接入库。
3. **项目规划**：表格导入、字段映射、拆解预览、项目甘特图、十阶段项目进度、每日提醒设置。
4. **定时任务**：工作台内每日 T5T 启停、执行时间、工作日例外、立即生成、日报查看与导出。
5. **工作**：项目任务、生命周期阶段、负责人、优先级、起止日期、预计工时、完成状态。
6. **学习 / 自媒体 / 灵感 / 习惯 / 情绪**：沿用原有模块卡片与统计。
7. **数据与帮助**：JSON 导入、导出、使用指南、恢复示例数据。

### 十阶段自动拆解

完整 SOP 按你的真实工作流生成任务，而不是通用五步模板：

`讨论调研 → 规划立项 → 决策评审 → 设计 → 研发协同 → 测试验收 → 上线发布 → 培训赋能 → 运营推广 → 复盘`

内置个人工作纪律：

- 立项前补充 **30 分钟用户/数据调研纪要**。
- 需求评审后 **48 小时内修改对齐**。
- 设计/UI 评审、技术方案评审、接口字段对齐、测试用例评审、提测、联调/冒烟均形成任务。
- UAT 说明会与结果反馈闭环，验收必出报告。
- 发布准备会后按 **周五自测、周一上线、周五不发布** 执行；已排到周五的上线任务自动挪到周一，并在提醒中标红冲突。
- 上线后输出上线说明与操作说明，开展内部/客户/渠道分层培训，准备运营货盘和推广清单。
- 上线 **两周内** 固定复盘并回流需求池。

拆解方式可选「完整十阶段 SOP / 每阶段一个关键动作 / 保留原任务」，生成范围可选「全部阶段 / 当前阶段及后续 / 仅当前阶段」。预览中的项目、任务、阶段、负责人、优先级和日期都可修改，确认后才写入工作台。

## AI 对话拆解

侧边导航「AI 拆解」是一个对话式入口，与「项目规划 → 导入规划表」共用同一套十阶段拆解规则，产生完全相同的任务结构。

### 两种输入方式

- **对话输入**：一行一件事，或用 `1. / - / ；/ 。` 分隔多条。支持 `项目：会员端 V2`、`负责人：朱萍萍`、`@某人`、`优先级高 / P0 / 紧急` 等写法。
- **上传任务表**：点击「上传任务表」选择 XLSX / CSV / TSV，自动识别列名并按行拆解；识别不到「规划事项 / 需求」列时会明确提示，并引导到导入弹窗手动映射。

### 日期识别

支持 `2026-12-15`、`12 月 15 日`、`12/15`、`今天 / 明天 / 后天 / N 天后 / N 周后`、`本周五 / 下周一 / 下下周三`、`本月底 / 下月底`。一句话里出现两个日期时按「开始 → 截止」处理；只出现一个日期时作为截止/上线日期，起点自动往前推。所有日期按 Asia/Shanghai 计算。

拆解后延续你的工作纪律：上线任务自动落到**周一**、复盘固定在上线后 **14 天**，并补齐调研纪要、评审后 48 小时对齐、发布准备、分层培训等环节。

**关于拆解粒度**：对话里**不需要先选粒度**，默认按完整十阶段拆。生成后如果觉得太细或太粗，直接在预览卡上点「完整 / 精简 / 原样」切换，任务会即时重算；也可以回一句「精简点」「按原样」来调整上一条预览。只有你说出来（或点了按钮）才会变，不会在动手前先拦你一道。

### 结果入库

对话里生成「拆解预览卡」，列出项目、任务、阶段、负责人和截止日期；点击「加入工作台」后写入 `work` 与 `projects`，按钮变为「已加入工作台」并可一键跳到甘特图。已经入库的预览不会重复写入。

### 关于「AI」与模型

- **默认走本地规则拆解**：完全离线、无需密钥，界面明确标注「本地规则」，不会伪装成调用过模型。
- **可选接入大模型**：在「模型设置」里填 OpenAI 兼容的 `chat/completions` 地址、模型名和 API Key。配置成功后对话会先请求模型，要求模型返回结构化任务条目；模型结果再送入同一套十阶段规则展开。
- **失败自动回退**：接口不通、CORS 拒绝、超时 30 秒或返回格式不对时，会显示明确的错误提示，并自动改用本地规则继续拆解，不会卡住对话。地址缺路径时，「测试连接」会自动按 `/chat/completions` 补全重试一次，补全成功会把新地址写回输入框并保存。
- **密钥安全**：模型配置只存在浏览器 `localStorage` 的独立键 `sanyuan.assistant.model.v1` 中，**不写入工作台数据、不进入 JSON 备份、不随导出文件外传**。清除浏览器数据会一并清除。
- **边界**：纯静态页面直连第三方模型受对方 CORS 策略限制；本工作台不内置任何模型、不代管密钥、不提供代理服务。

### 「测试连接」失败怎么排查

「测试连接」会真发一次最小请求，并把接口**实际返回的内容**（HTTP 状态、Content-Type、响应开头、是否被重定向）回显出来，而不是只给一句 JSON 解析报错。常见提示与对应改法：

- **「接口返回的是 HTML 网页，不是 JSON」**：请求打到了一个页面，不是 API。通常是接口地址填成了网站首页/后台地址、缺 `/chat/completions`，或被登录页、SSO、网关拦截后跳转（回显的「发生了重定向 →」能看出来）。先核对地址是否为完整的 `chat/completions` 地址。
- **「接口返回 HTTP 401 / 403」**：通常是 API Key 无效、模型名不存在或无权限，核对 Key 与模型名。
- **「网络不可达或被跨域（CORS）策略拦截」**：浏览器不允许页面直连该接口，需要接口方允许跨域，或改走自建服务端代理。
- **「返回 JSON 缺少 choices[0].message.content」**：接口不是 OpenAI 兼容格式，确认路径与接口形态。

## 工作台内 T5T 定时任务

已在侧边导航新增「定时任务」，不再使用 WorkBuddy 自动化；此前创建的 WorkBuddy 每日 T5T 任务已删除。

- **启停**：页面内的「暂停定时任务 / 启用定时任务」按钮，或开关后保存设置。
- **默认时间**：每天 18:30，按 Asia/Shanghai（UTC+8）判断。
- **工作日**：默认「中国大陆工作日」模式，按周一至周五判断；「工作日例外设置」可维护法定节假日和调休上班日。节假日跳过并标记，调休工作日照常生成。
- **生成内容**：今日完成 Top 5、次日待办 Top 5、风险与未闭环、数据完整度；可查看、复制 Markdown 或导出 `.md`。
- **自动生成**：到点后由页面内的本地调度器生成，每天一次；如果页面重新打开时已过执行时间且当天尚无日报，会补生成一次。
- **数据来源**：默认读取工作台任务完成记录；钉钉日志/日历可手动粘贴作为补充。纯浏览器页面无法直接调用钉钉 API，也不会自行读取钉钉账号。
- **历史保留**：最近 60 份日报保存在 `localStorage` 与 JSON 备份中。
- **运行限制**：这是纯本地页面定时任务，只有工作台页面打开时才会自动执行；关闭浏览器后不会后台运行。若需要关机也能运行，需要另配后端或系统级服务。

## 每日提醒规则

页面内提醒按以下顺序自动排序：`周五发布冲突 → 已逾期 → 今日到期 → 今日启动 → 未来 3 天到期`。总览显示前 5 项，项目规划页显示全部；顶部铃铛显示待关注数量。

可设置每日提醒时间并授权浏览器通知。授权后，页面保持打开且到达设定时间时发送一次系统通知，同一天不会重复发送。**纯本地页面关闭浏览器后不会后台推送**；如需跨设备/关闭页面后的定时推送，需要另接日历、企业微信或自动化服务。

## 部署到 GitHub Pages

- 仓库：<https://github.com/feichenanyu/sywork>（公开，默认分支 `main`）
- 线上：<https://feichenanyu.github.io/sywork/>

`.github/workflows/pages.yml` 在 push 到 `main` 时自动构建并发布，采用 GitHub 官方组合：`configure-pages@v5` → `upload-pages-artifact@v3` → `deploy-pages@v5`。流水线先 `Stage site files`，把 `index.html`、`styles.css`、`app.js`、`spreadsheet.js`、`.nojekyll` 五个站点文件复制到 `_site/`，只上传这个小目录并显式命名 artifact 为 `github-pages`（`retention-days: 1`）。直接上传整个仓库根目录时曾偶发 `No artifacts named "github-pages"` 的索引竞态，缩小上传内容后部署恢复稳定。`enablement` 由仓库的 Pages 设置决定，流水线不改写 Pages 来源。

本地改动后同步：

```bash
git add -A
git commit -m "说明改了什么"
git push origin main
```

推送后约 1 分钟 Actions 跑完，线上即更新。可在仓库 Actions 页查看 `Deploy static site to GitHub Pages` 的运行结果。

> **配置与数据按来源隔离**：模型配置（endpoint / model / API Key）和六模块记录都存浏览器 `localStorage`，`file://` 本地打开、WorkBuddy 预览面板、`github.io` 线上三者互不相通。线上首次使用需要在该页面重新配置模型；本地录入的记录也不会出现在线上。
